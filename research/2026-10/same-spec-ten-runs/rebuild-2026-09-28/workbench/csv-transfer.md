# CSV 教學重播：先修驗收，還是重新生成？

這是一個使用固定資料與 Python 標準函式庫的教學，不是作者 repo 的第二個正式研究任務。它沒有模型請求、沒有 subprocess，也沒有執行正式四十份候選。程式與自測合計 150 行；實際輸入、輸出文字、完整 bytes 的十六進位表示及 SHA-256，均保存在 [csv-transfer-results.json](csv-transfer-results.json)。

## 一、先確定哪些選擇已經作出

本例沿用 [大綱讀者審查](../outline-evidence-reader-review.md) 的三筆資料。假設 owner 已決定：空日期以空欄輸出，保留輸入列序與重複列，header 名稱與欄序固定為 `name,date,note`。Record delimiter 可用 LF 或 CRLF；欄位內容中的逗號與換行必須保留。

如果 owner 尚未決定空日期的政策，應先處理這個問題，不能讓測試作者自行決定 expected output。以下重播只在上述選擇成立時才有依據。

```json
[
  {"name":"王,小明","date":null,"note":"第一行\n第二行"},
  {"name":"李","date":"2026-09-28","note":""},
  {"name":"李","date":"2026-09-28","note":""}
]
```

因此，驗收先寫下預期 header，以及依序排列的三筆 records：王小明的姓名仍含逗號，日期成為空欄，note 仍含欄位內換行；後面兩筆相同的李都要留下。這些預期值在程式中直接依契約寫成常數，沒有呼叫匯出函式取得答案，也沒有拿匯出結果回填成 expected records。

## 二、三種驗收方式，會作出不同判斷

[csv_transfer.py](csv_transfer.py) 使用 `csv.writer` 產生兩種合法表示，分別使用 CRLF 與 LF。它另建立四份刻意錯誤的輸出：去除重複列、交換 header 欄名、改變資料順序，以及改掉一個日期值。這些是事先安排的測試資料，不是 agent 曾犯錯的紀錄。

每一份輸出都交給三種判斷方式：第一種只檢查 `csv.reader` 能否解析；第二種與 CRLF 範本逐 byte 比對；第三種先解析，再分別核對 header 與完整、有序的 records。第三種保留重複資料，不先轉成集合或排序。

實際重播結果如下。實體行數包含 header；欄位內有換行，所以文字有五行，不代表有五筆資料。

| 輸出 | 實體行數 | Records | 只要解析成功 | 與 CRLF 範本 bytes 相同 | 核對 header 與有序 records |
|---|---:|---:|---|---|---|
| 合法 CRLF | 5 | 3 | 接受 | 接受 | 接受 |
| 合法 LF | 5 | 3 | 接受 | 拒絕 | 接受 |
| 擅自去重 | 4 | 2 | 接受 | 拒絕 | 拒絕 |
| header 欄名次序錯誤 | 5 | 3 | 接受 | 拒絕 | 拒絕 |
| 資料列序錯誤 | 5 | 3 | 接受 | 拒絕 | 拒絕 |
| 一個日期值錯誤 | 5 | 3 | 接受 | 拒絕 | 拒絕 |

逐 byte 比對把合法的 LF 拒絕，因為範本只保存了一種允許的表示。只檢查能否解析則走到另一個極端：四種錯法都是可解析的 CSV，但已違反欄序、列序、值或保留重複列的要求。解析是理解輸出的步驟，後面仍需要依契約判斷內容。

第三種驗收在這六份固定資料上作出了預期判斷。它沒有證明所有 CSV 格式與所有匯出行為都已受保護，也沒有替任何規格寫法增加成功樣本。

## 三、讀者現在可以作什麼決定

若手上的驗收只接受 CRLF bytes，就先修正驗收方式，讓它接受契約允許的 LF。保留舊的範本與判分紀錄，再以新版 oracle 對同一批已存在輸出一致重評；這一步不需要新的模型生成。修正後仍應用去重、錯 header、錯列序與錯值的對照，確認沒有為了放寬合法表示而把內容要求一起放掉。

若候選真的去除了重複列，則拒絕這份候選，回到保留重複資料的要求。這項輸出差異本身不能說明模型是漏讀、誤解還是選錯 helper，更不能證明增加六點自查就會改善。要決定自查是否成為預設交代，仍需另行比較文件介入、交付結果與人力成本。

本例只要求完成後交出 CSV 檔案，沒有要求逐筆即時輸出。因此也不能照抄 JSONL parser 的 EOF 前 streaming probe：是否需要串流，應由 caller 的需求決定。

## 四、如何重播與核對

從 repo 根目錄執行，僅需 Python 3.10 以上與標準函式庫：

```sh
python3 -B research/2026-10/same-spec-ten-runs/rebuild-2026-09-28/workbench/csv_transfer.py --output research/2026-10/same-spec-ten-runs/rebuild-2026-09-28/workbench/csv-transfer-results.json
python3 -B -m unittest discover -s research/2026-10/same-spec-ten-runs/rebuild-2026-09-28/workbench -p test_csv_transfer.py -v
```

第一個指令重新產生結果檔，更新執行時間、Python 版本與兩支程式的 SHA；固定輸入及輸出都附有各自的 hash，可獨立核對 bytes。第二個指令執行 [11 項自測](test_csv_transfer.py)：接受兩種合法表示，拒絕去重、錯 header、錯順序與錯值，確認逗號、欄內換行、空日期與重複資料保留，並檢查無效 UTF-8 與未閉合引號會被拒絕。

本次使用 CPython 3.14.5，11 項自測全數通過。這 11 項只確認本教學裝置的指定行為，與原 workbench 的 26 項檢查分開，也不加入正式研究的四十個生成名額或 103 項驗收。

例子中的非空日期本來就是 `2026-09-28`，程式直接保留，沒有驗證日期格式轉換、其他日期輸入、所有 CSV dialect 或整套匯出工具。這份驗收只檢查固定 header 與解析後的 records，並非完整的 CSV 格式驗證器。跨 Python 版本或其他環境是否維持相同行為，也需由重播結果確認。
