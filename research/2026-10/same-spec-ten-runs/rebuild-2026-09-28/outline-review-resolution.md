## Research loop 的執行方式

本輪依 repo 的流程推進：collect → digest → proposal／outline → evidence／reader／editor／diagram review → write → review／revise → 語言與發布包驗證。環境沒有原生 Workflow 執行入口，因此使用本機資料、獨立研究代理與 CLI adapter，保存相同階段的輸入、來源版本、輸出與處理紀錄，沒有宣稱已執行原生 workflow。

來源查證統一使用 gstack browse；既有實驗資料保持唯讀，事後新增的教學另行保存。主寫維持作者指定的 Claude Code Opus 5.5 max。第一次以 Claude xhigh 進行架構挑戰審查時，因 session 額度限制而未產生有效 review；CLI 當時回報額度將於臺北時間 04:00 重置。這次沒有結果的呼叫，不計為已完成審查。

現階段的架構審查由 Codex 代理完成，與後續 Claude 主寫構成跨模型協作；不能因此寫成 Claude 已審過新大綱。

## Evidence／reader 的五項 major

| 問題 | 處理方式 | 已核對位置 |
|---|---|---|
| Policy 未定，trial 成功可能回答錯問題 | 下一輪明定 session 可以使用工具，但有明確限制。公開 check 與自行修正都在 session 內完成，session 結束後才進行外部驗收，不另開新 session 替補。主要結果、人工救援與最後交付分欄記錄；正式 40 次仍屬於原本的無工具研究。 | `comparison-plan-example.md` 第一、二節的單位定義與人工觀測；提案與 `writer-facts` 已同步。 |
| 抽樣框與診斷 pilot 不清楚 | 完整保存收到的工作清單，包含被排除或尚無法驗收的工作。歷史已合併題另限於 backtest，seed 取自修補前。刻意錯法只用來檢查與修正量尺，不能在精度規劃時把這些結果當成母體錯誤率。 | 比較卡第二節的任務來源；大綱末段的主寫決定。 |
| 人工採用條件缺少觀測設計 | 全量保存人工實際接手的時間。事前制定深讀的分層抽樣規則，取得結果後再依規則抽取；同時安排 reviewer 與閱讀順序，記錄盲化限制及同題學習效應。沒有真人資料，就無法確認共同的採用條件已成立。 | 比較卡第二節的人工觀測、第五節的門檻。 |
| Pilot、有限試行與預設採用混用 | 分成診斷 pilot、保留既有人類核准的有限部署 trial，以及依門檻決定的預設採用。若 CSV 政策未定或 oracle 有錯，可以先處理該問題，不必立刻作 P／Q 比較。 | 比較卡第三節、提案末段，以及總論的主寫任務。 |
| Regression 與公開題目的用途混淆 | 區分固定 fixtures 測 grader、新候選測契約，以及新生成測 model／harness。原資料可作回歸資產，但公開資料的副本不能變成未見的 holdout。 | 比較卡第四節、證據表與大綱。 |

主代理另將候選必要條件與方法層的風險門檻分開：單份候選違約，不能用其他測項得分抵銷；跨 trial 比較仍保留失敗，不能偷偷增加「觀測必須零失敗」的規則。方法層的暫停條件，則需要在執行前另行決定。

## Editor／diagram 的四項 major 與 minor

| 問題 | 主寫前的處理 | 成稿還要驗證什麼 |
|---|---|---|
| 工作坊 10/16 被誤寫成十項未通過 | 主代理對照《綠燈不是驗收》與現行稿，修正為 16 項中通過 10 項、未通過 6 項；錯誤數字沒有進入新主稿。 | 全文回憶、TL;DR 與圖表中的數字都須一致，不能把兩套檢查混成同一個成功率。 |
| 四份卡片可能無法銜接 | 主要介入固定為 P 採展開規格，Q 再加六點自查；四篇各自完成下一步判斷。CSV 案例沿著政策、文字、oracle、方法採用的順序，示範如何轉用方法。 | 每篇不依賴預告，也能完成一個決定；拿掉其中一篇時，應能指出讀者會少掉哪種能力。 |
| 可能機制被寫成因果 | 保留可觀察的錯法、替代解釋、介入假說，以及能支持或削弱假說的觀察。正式研究沒有工具，新設計則可使用工具，兩者必須分清。 | 不從錯碼推測模型的心理活動，也不能只憑整組介入效果，就判定理由或自查各自帶來多少收益。 |
| 表格與後半部取代推論 | 完整範本留在附件，正文只呈現當下需要的已填欄位；各篇最後三分之一都必須完成一次有理由的教學決定。 | 表格後須有推導，交代為何排除其他選擇、由哪位 owner 接手，以及符合什麼條件才能恢復判定。 |

Minor 已處理：原始檔案的 SHA-256 對應內容身分；normalized AST hash 只識別正規化後的表示，不能確認原始檔案逐 byte 相同。不得籠統地寫「hash 就是版本」。

概念圖只保留兩個用途明確的圖：總論用來分流，判斷下一步需要哪種證據；契約篇則用來說明 EOF 前的觀察時序。Mermaid 版型已通過 repo 檢查，並由主代理目視核對，詳見 `figures.md`。圖表數量不作為看齊既有系列的標準。

## 總論成稿後補正：自查的跨任務改寫

此補正晚於三篇主筆 prompt 的封存，供主代理潤稿及後續審查使用，不回寫已送出的 prompt。Parser 的 worked example 可比較展開規格與凍結 B 六題原文；跨任務則不能直接套用 EOF、token 或 R09 等義務。下一輪目標改明確定義為「依事前固定政策改寫自查」：只指向各 task 的 P 已揭露要求，不適用項目按事前規則處理，不藉 Q 增加要求或帶入隱藏 grader／參考 patch 資訊。各 task 的 P／Q 先核對、封存，同 task 同 arm 的重複內容逐 byte 相同。效果屬這套改寫政策，不是原六句或第二題的單獨效果；映射與維護也計入人工投入。

完整任務映射與 packet 尚未完成，48×2×3 仍只是預算草案，不能作為可直接執行的規範。詳見 [自查改寫政策](self-check-transfer-policy.md)。必要行為與相容責任不必等待此可選介入的效益比較。
