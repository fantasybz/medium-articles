# Harden the repository's Codex JSONL review parser (compact specification)

Modify only the supplied `codex_jsonl.py`, copied unchanged from medium-articles commit `37f6c0ce9b536f95132d5e01a387f380bbb9639c`. Fix valid-JSON wrong-type crashes and prevent non-text values from becoming a successful review. The requirements below are the complete contract. This is a maintenance task; preserve the existing permissive stream behavior.

### R01 — Artifact and CLI

Submit one regular file, `codex_jsonl.py`, not a symlink, using Python's standard library. Keep its CLI/main entrypoint. Read stdin as UTF-8 JSONL, emit review content on UTF-8 stdout, diagnostics on stderr, and retain flushing so valid output appears before stdin EOF. Do not buffer the full input before processing lines. CJK must survive a C locale. No new CLI arguments or external dependencies are required. Extra fields in objects are ignored.

### R02 — Lines and event dispatch

Count physical input lines starting at 1, including blank and non-JSON lines. Strip each line as before. Blank lines and text that cannot be decoded as JSON are silently skipped. A decoded non-object (array, null, string, number or boolean) is malformed. A root object with no `type` is ignored; a provided non-string `type` is malformed. Unknown string event types are ignored without validating their payload. Recognized types are `item.completed`, `turn.completed`, `turn.failed`, `error`.

### R03 — Malformed event handling

For each malformed line, emit exactly one stderr line `[codex malformed event] line N: REASON\n`, where N is its physical line number and REASON is any nonempty single-line explanation. Remember the malformed condition and continue reading; never raise a traceback or stop processing later events. The malformed event on that line contributes no stdout and does not count as a completed turn or agent message. The one exception to dropping semantic effects is `turn.failed`: it always records explicit failure and emits its legacy failure diagnostic, as in R10. Do not add a new end-of-stream summary for malformed events.

### R04 — Completed-item envelope

For `item.completed`, missing `item` means `{}` (ignore it); provided `item` must be an object, so null is malformed. Missing item `type` is ignored; provided item `type` must be a string. Unknown string item types are ignored without inspecting their other fields. Recognized item types are `agent_message`, `command_execution`, `error`.

### R05 — Agent text

For an agent_message, missing `text`, null and empty string mean no message and produce nothing. A provided non-string/non-null text is malformed, including 0, false and empty arrays/objects. A nonempty string is printed unchanged plus one newline, flushed, and counts as a spoken agent message. Do not strip the message; whitespace-only strings remain valid for legacy compatibility.

### R06 — Command comment

For command_execution, missing `command`, null and empty string are ignored. Any other provided non-string is malformed. A nonempty string produces exactly `<!-- codex ran: S -->\n` on stdout, flushed, where S is its first 160 characters (not bytes). This is not an agent message.

### R07 — Item error diagnostic

For item type error, missing `message`, null and empty string are ignored. Any other provided non-string is malformed. A nonempty string emits exactly `[codex item error] MESSAGE\n` on stderr, flushed. Item errors do not set the explicit turn-failure flag and do not count as agent messages.

### R08 — Completed turn and usage

For `turn.completed`, missing `usage` means `{}`; provided usage must be an object, so null is malformed. Inside usage, missing `input_tokens` or `output_tokens` defaults to 0. Each provided token value must be an integer >=0, excluding booleans; floats, strings, null, containers and negative integers are malformed. Ignore other usage fields. Validate the entire usage before counting the completion or printing. A valid event counts as one completed turn and emits exactly `\n<!-- tokens: in I out O -->\n` on stdout, flushed.

### R09 — Top-level error

A root `error` event always sets explicit failure and prints exactly `[codex error] M\n` to stderr, flushed. M is `str(event.get("message", ""))`, preserving the old conversion for every JSON value (including null/numbers/containers); no message-type restriction is added for this event.

### R10 — Failed turn

A `turn.failed` event always sets explicit failure. Missing `error` or null uses message `no message`. A provided non-null error must be an object. Inside it, missing/null/empty-string `message` uses `no message`; a nonempty string is used unchanged. A provided non-string/non-null message, or a non-object/non-null error, is malformed: emit the R03 line first, then use `no message`. Always emit `[codex turn FAILED] MESSAGE\n` on stderr, flushed, including malformed failed-turn events.

### R11 — Exit-code precedence

After EOF choose exactly: 3 if any explicit failure; else 6 if any malformed event; else 4 if no valid completed turn; else 5 if no actual nonempty string agent message; else 0. Continue processing after any error so later explicit failure outranks earlier malformed events. The exit-6 condition never turns previously printed streaming content into a success.

### R12 — Legacy end diagnostics

For exit 3 append exactly `[codex] the turn failed (reason above); no review was produced.\n` to stderr. For exit 4 append exactly `[codex] no turn.completed event: possible mid-stream disconnect.\n`. For exit 5 append exactly `[codex] the turn completed without an agent message; no review was produced.\n`. Exit 0 and exit 6 have no end summary. Existing valid output and diagnostic text must otherwise stay unchanged.

### R13 — Preserve permissive stream behavior

Do not add sequence, uniqueness or terminal-state validation. Repeated identical agent messages are printed/count separately. Multiple valid turn.completed events each print their own token comment. Events after a completed turn are still processed. Extra fields, unknown string event/item types, blank lines and non-JSON text retain the compatibility rules above. This task does not add a strict mode, reject duplicate terminals, or change the shell wrapper.
